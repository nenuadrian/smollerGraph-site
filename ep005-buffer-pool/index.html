    Database buffer pool in C++: keeping pages in memory

    A buffer pool for smollerGraph, with frames, a page table, pins, dirty pages and the clock, and what it does to a million relationships.

Loading a million relationships read and wrote over six million of them, a system call each. The pool has frames, a page table, pins and dirty pages, and a clock that picks the page to evict. A latch keeps sg serve's threads out of each other's way, and we measure it all again against Neo4j and Kùzu, and look at why databases keep a pool of their own instead of using mmap.

    A buffer pool

    4:42 A buffer pool keeps a database's pages in memory, so the pages it uses most are read from disk once, and changed in memory as often as it likes. The file is still where the pages live, and the pool has a number of frames, each a page-sized piece of memory that can hold one of them. A table says which frame holds which page, so finding a page in the pool is a lookup in a hash map. A page that someone is using is pinned, and a pinned page stays where it is. A page that was changed is dirty, and it's written back to the file before its frame is given to another page. And when the pool is full, something has to pick which page leaves: we're going to use the clock, which PostgreSQL uses a version of too. Neo4j calls its pool the page cache, and Kùzu calls its the buffer manager, and both are sized to hold a graph like ours.

    5:31 The clock is a hand that goes round the frames, each of which has a referenced bit, set each time its page is fetched. When the pool needs a frame, the hand moves on from where it stopped. A page that was referenced since the hand last came by gets a second chance: the hand clears its bit, and moves on. A pinned page is skipped, as someone is using it. And the first page that's neither referenced nor pinned is the one that goes, so pages that keep being used keep their frames. It costs a bit for each frame, instead of a list in order of use, which is why databases like it.

    6:07 You might be wondering why a database doesn't let the operating system do this, as it already keeps files in memory, and mmap can map a file into a program's memory.
