    smollerGraph: Building smollerGraph: A Graph Database from Scratch

    A graph database, from the bytes up.

    We're going to build a small graph database from scratch in C++: how it keeps nodes and relationships on disk, how it follows them from one to the next, and how a Cypher query becomes a plan that runs, measured against Neo4j and Kùzu, on the way to a knowledge graph that mvGPT can ask for facts.

    1. FastRP node embeddings in a graph database

      Node embeddings in smollerGraph with FastRP, as Neo4j's Graph Data Science library computes them, the most similar nodes by cosine, embeddings kept on disk, and a page that draws a node's nearest.

    2. Dijkstra's algorithm in a graph database

      Weighted relationships and cheapest paths in smollerGraph, with Dijkstra's algorithm and a priority queue, then from both ends, Kùzu's WSHORTEST in Cypher, and weights on the page.

      28 min

    3. Shortest paths in a graph database

      Shortest paths in smollerGraph, with a breadth-first search that keeps each node's parent, then two of them that meet in the middle, shortestPath in Cypher as Neo4j writes it, and a path drawn on the page.

      34 min

    4. Reverse traversal and query planning

      Relationships followed both ways in smollerGraph, with labels and types as tokens to make room for a second chain, Cypher that points left, plans that start from a name, and a fair benchmark in Cypher.
